# 骨骼锚定图生成系统 · 目标定义

> 一句话：AI 剧生成之前，先用一张骨架示意图把「这场戏有几个人、站哪、什么姿势、朝哪」钉死，让人先确认、让 AI 不瞎脑补。

日期：2026-11-17
状态：目标已锁定，待进入方案设计

---

## 1. 要解决什么问题

剧本里写「三个人在客厅争执」，AI 直接生成经常翻车：人数不对、站位乱来、谁在谁前面全错。

这套系统插在**剧本**和**AI 剧生成**中间，先把空间关系锚定成一张图。这张图只讲**关系**，不讲画面——运镜、切换、剪辑、光影这些全交给下游 AI 发挥。

## 2. 成品形态

- **网页可视化工具**：左边剧本文本，中间画布拖拽，右边导出图。
- 输入**该场景**的剧本文本，输出**一张静态示意图**。
- 系统活干到导出图为止，**不负责**后面的文生视频调用。

## 3. 完整流程

1. 贴入该场景的剧本文本
2. AI 解析出人数、站位、姿势、关键道具，生成初稿
3. 人工在画布上拖拽节点微调（位置、姿势、朝向）
4. 导出一张锚定图
5. 把**图 + 剧本**一起喂给下游文生视频大模型

## 4. 锁定的决策清单

| 维度 | 结论 |
|---|---|
| 产物 | 一场景一张静态骨架示意图；2.5D 斜俯视 + 地面网格 |
| 输入 | 只喂该场景的剧本文本 |
| 打底方式 | AI 解析剧本出初稿，人工拖拽微调 |
| 微调方式 | 网页画布拖拽节点，所见即所得 |
| 姿势落地 | 预设姿势模板库（站/坐/走/挥手/背对等）；AI 按剧本先选一个，人工再调 |
| 朝向表达 | 靠火柴人画法本身体现，不额外写文字 |
| 人物标注 | 图上只标角色名标签 |
| 关键道具 | 影响站位的道具也要标，写道具名 |
| 图风格 | 纯示意图，施工图感，不是画面预览 |
| 关系语义 | 只表达前后 / 左右 / 朝向等相对关系，**不锁机位** |
| 约束强度 | 机位自由，下游 AI 可换视角，只要不违反相对关系 |
| 是否要动 | 静态图就够，不做动画 |
| 交付形态 | 只交付一张图；图 + 剧本一起喂下游 |
| 下游工具 | 通用文生视频大模型（可灵 / 即梦 / Sora 这类） |

## 5. 锚定图里有什么

- **地面**：2.5D 斜俯视透视网格，前大后小体现纵深
- **人物**：火柴人，带角色名标签；姿势从模板库选，朝向靠画法体现
- **道具**：影响站位的关键道具，标名字（如「茶几」）
- **不画**：性别、年龄、服装色等属性（见第 6 节）；连线和箭头（本轮未选）

## 6. 系统边界（明确不做的）

1. **不做动画**：名字虽叫「骨骼动画系统」，实际产物是静态图。
2. **不管人物属性**：性别 / 年龄段 / 服装主色这些是**另一套人物建模系统**的事。本系统只认角色名（角色 ID），人物对应关系通过角色名和那套系统对接，不重复维护属性。
3. **不锁机位**：不写死运镜、切换、剪辑，这些交给下游 AI。
4. **不调文生视频**：只出图 + 剧本，喂给下游的动作不在本系统内。
5. **不出结构化数据**：这一版只要一张图，不额外输出 JSON。

## 7. 待进入方案设计时再定的

- 姿势模板库具体收哪些姿势、够不够用
- AI 解析剧本的具体实现（怎么从文字判断人数 / 站位 / 姿势）
- 画布交互细节（拖拽手感、吸附、撤销重做）
- 导出图的格式和分辨率
- 和人物建模系统之间角色名的对接方式
